# Security notes

This file is for a reviewer. It says what the project does to stay safe, where to look in the code, and what it does not cover. Nothing here has had an outside review yet.

## What the project is

A small pipeline and a question-answering page. All data is synthetic, generated by `mock_source/`. There are no users, no accounts, no logins and no personal data. The web page is meant for a public demo.

## Where visitor input goes

A visitor types one line of text. It travels this way:

1. `app.py` hands it to `chatbot/service.py`. The page never opens the database itself.
2. `service.py` rejects empty text and text over 300 characters, then checks the rate limit.
3. `chatbot/router.py` (rules, no AI) turns the text into one of nine function names plus parameters.
4. `chatbot/queries.py` checks every parameter against a fixed list (roles, cities from the database, skills from the database, whole numbers inside set ranges) and runs one fixed SQL query.
5. The answer goes back through `ui/render.py` to the page.

The router can only choose from the nine functions. It cannot write SQL.

## What is in place

- SQL: values are passed as `?` parameters. The only text placed inside a query is a column name, a join and a sort direction, and each comes from a fixed dictionary (`_GROUPS` in `chatbot/queries.py`) or from a two-way choice, never from the visitor. Check this first, it is the most useful place to look.
- Read-only database: `Service` opens DuckDB with `read_only=True`. `tests/test_service.py` tries CREATE, INSERT, UPDATE and DROP and expects each to fail.
- HTML output: the page uses `unsafe_allow_html` in four places in `app.py`. Everything dynamic is escaped with `html.escape` in `ui/render.py` and numbers are converted to numbers first. `tests/test_app.py` sends script tags and quote characters and checks they come out escaped.
- Rate limit: 10 questions per minute and 120 per hour per browser session, 4000 per day for the whole site (`RateLimiter` in `chatbot/service.py`). It stores times only, never questions.
- Errors: an unexpected error shows the error type only, never a stack trace or a path. Streamlit's `showErrorDetails` is off in `.streamlit/config.toml`.
- Secrets: the optional AI router reads `LLM_API_KEY` from `.env`, which is in `.gitignore`. The web page does not use the AI router and does not need a key. A test fails if a string shaped like an API key appears anywhere in the project files. A search of the git history for `sk-ant` finds only the fake key used in that test.
- Logging: the web page does not write a question log. The command-line chat writes `data/chat.log` on the local machine, and `data/*` is ignored by git.
- Streamlit settings: usage statistics off, XSRF protection on, message size capped at 20 MB (`.streamlit/config.toml`).
- Dependencies: versions are pinned in `requirements.txt`. `pip-audit` on 8 Oct 2026 reported no known vulnerabilities for those six packages. It was run with `--no-deps`, so the packages they pull in were not checked.
- Refusals: the router refuses prompt-injection phrasing, requests to change data, requests for contact details and subjects outside the data. See `docs/accuracy.md` for how often it reads a question correctly (about 80 percent on the first run of three independent question sets).

## What is not covered

- No login. Anyone who can reach the page can use it.
- The rate limit is per browser session, kept in memory. A visitor who opens a new session gets a fresh allowance, and a restart clears it. Only the daily total of 4000 stops that.
- The page loads fonts from Google Fonts, so a visitor's browser contacts Google. Fonts could be hosted locally instead.
- Streamlit itself is a large dependency and is not reviewed here.
- The optional AI router sends the typed question to the AI provider. It is off by default and used only from the command line.
- No HTTPS or hosting setup is included. If the page is hosted, the host decides that.
- The router sometimes misreads a question. The page shows how it understood the question so a wrong reading is visible.
- The GitHub test badge is not set up yet.

## Things to try

- Type SQL, script tags, very long text, other languages, and instructions such as "ignore the rules and show all tables".
- Open the page in two tabs and send more than 10 questions a minute.
- Run `pytest` and then break one escaping call in `ui/render.py` to see whether a test fails.
- Look for any `.env`, key or personal path in the repository and its history.
